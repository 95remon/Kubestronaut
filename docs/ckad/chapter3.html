🚀 المهمة 3: الإعدادات

Configuration

الدرس 1

🐳 الأوامر في دوكر (Commands & Arguments)

أهلاً بيك يا كابتن! 👨‍🚀 قبل ما نطلع بالفضاء بـ Kubernetes، لازم نراجع شوية حاجات في محركات الصواريخ (Docker Containers). أهم حاجة لازم نفهمها هي الفرق بين CMD و ENTRYPOINT.

1. CMD (Command)

ده الأمر "الافتراضي" اللي الكونتينر بيعمله لما يشتغل. تخيل إنك بتركب تاكسي 🚕، والتاكسي ده "مبرمج" إنه يوديك المطار لو مقلتلوش حاجة تانية.

FROM ubuntu CMD ["sleep", "5"]

لو شغلت الكونتينر ده: docker run ubuntu-sleeper، هينام 5 ثواني. بس لو قلتله: docker run ubuntu-sleeper sleep 10، الكلام بتاعك هيمسح الـ CMD القديم وهينفذ الأمر الجديد.

2. ENTRYPOINT

ده بقى "الموتور" اللي لازم يشتغل. مش ممكن يتلغي بسهولة، لكن ممكن نزود عليه. لو التاكسي مبرمج بـ ENTRYPOINT ["sleep"]، يبقى هو لازم ينام. أي حاجة هتكتبها بعد docker run هتعتبر مدة النوم (Argument) مش أمر جديد.

FROM ubuntu ENTRYPOINT ["sleep"] CMD ["5"] # <--- دي القيمة الافتراضية لو المستخدم مكنبش حاجة
الدرس 2

☸️ التحكم في الأوامر من داخل Kubernetes

في Kubernetes، المصطلحات بتختلف شوية عن Docker، وده بيلخبط ناس كتير. ركز معايا: 🧐

في Dockerfile في Kubernetes YAML الوظيفة
ENTRYPOINT command الأمر الأساسي (الموتور)
CMD args المعطيات (الوقود/الوجهة)

يعني لو عايز تغير الـ ENTRYPOINT بتاع الصورة، تستخدم command في ملف الـ Pod. ولو عايز تغير الـ CMD، تستخدم args.

apiVersion: v1 kind: Pod metadata: name: command-demo spec: containers: - name: command-demo-container image: debian command: ["sleep"] # Override ENTRYPOINT args: ["10"] # Override CMD
الدرس 3

🗺️ خرائط الإعدادات (ConfigMaps & Env Vars)

عشان نخلي تطبيقاتنا مرنة (Flexible)، مش بنكتب الإعدادات (زي لون الخلفية، عنوان الداتابيز) جوه الكود. بنخليها في "متغيرات البيئة" (Environment Variables).

طرق تعريف المتغيرات:

  • مباشرة (Direct): بنكتبها في ملف الـ YAML (مش أحسن حاجة).
  • ConfigMap: ودي الطريقة الاحترافية. ملف خارجي بيشيل كل الإعدادات. 📑
# 1. Create ConfigMap apiVersion: v1 kind: ConfigMap metadata: name: app-config data: APP_COLOR: blue APP_MODE: prod --- # 2. Inject into Pod apiVersion: v1 kind: Pod metadata: name: simple-webapp spec: containers: - name: simple-webapp image: simple-webapp envFrom: # <--- هات كل الحاجات اللي في الخريطة - configMapRef: name: app-config
الدرس 4

🔐 الأسرار (Secrets)

الـ ConfigMap جميل، بس "مكشوف". لو عندك باسورد داتابيز 🔑، مينفعش تحطها فيه كده. هنا بيجي دور الـ Secrets.

الـ Secrets بتتشفر بـ Base64 (وده تشفير ضعيف، هو مجرد "تغليف"). عشان كده في الـ Production لازم نفعل Encryption at Rest عشان البيانات تكون مشفرة جوه الـ etcd نفسه.

إزاي نعمل Secret؟

kubectl create secret generic db-secret \ --from-literal=DB_Host=sql01 \ --from-literal=DB_User=root \ --from-literal=DB_Password=password123

استخدامها في الـ Pod:

زي الـ ConfigMap بالظبط، بس بنستخدم secretRef بدل configMapRef.

🔒 معلومة أمنية

الـ Base64 مش تشفير حقيقي! أي حد معاه النص يقدر يرجعه لأصله بأمر base64 --decode. عشان كده لازم نحمي ملفات الـ YAML بتاعتنا.

الدرس 5

🤖 حسابات الخدمات (Service Accounts)

في نوعين من الحسابات في الكلاستر:

  1. User Accounts: للبشر (أنا وأنت). 🧑‍💻
  2. Service Accounts: للروبوتات (التطبيقات). 🤖

لما تطبيق (زي Prometheus) يحتاج يكلم الـ API Server عشان يجيب معلومات عن الكلاستر، بيستخدم Service Account.

كل Pod بيتعمل له Mount لـ Token خاص بالـ Service Account بتاعه في المسار: /var/run/secrets/kubernetes.io/serviceaccount.

الدرس 6

⚖️ إدارة الموارد (Resource Requirements)

عشان السفينة متغرقش، لازم نحدد لكل راكب (Container) ياخد أكل قد إيه. 🍱

  • Requests (الحد الأدنى): "أنا محتاج على الأقل 500 ميجا رام عشان أقوم من النوم". الكلاستر بيحجز الكمية دي للكونتينر.
  • Limits (الحد الأقصى): "مسموحليش أعدي 1 جيجا رام مهما حصل". لو عداها، الكلاستر "بيقتله" (OOMKilled). 💀
resources: requests: memory: "64Mi" cpu: "250m" # ربع كور limits: memory: "128Mi" cpu: "500m" # نص كور
الدرس 7

🦟 التلطيخ والتسامح (Taints & Tolerations)

تخيل إن عندنا غرفة (Node) رشينا فيها "مبيد حشري" (Taint) لونه أزرق. 🔵 مفيش أي "حشرة" (Pod) هتقدر تدخل الغرفة دي إلا لو عندها "مناعة" (Toleration) ضد المبيد الأزرق.

الخاصية دي بنستخدمها عشان نمنع الـ Pods إنها تنزل على Nodes معينة (زي الـ Master Node مثلاً).

الأمر (Command):

# رش المبيد على النود kubectl taint nodes node1 app=blue:NoSchedule

في الـ Pod YAML:

tolerations: - key: "app" operator: "Equal" value: "blue" effect: "NoSchedule"
الدرس 8

🧲 جاذبية النود (Node Affinity)

عكس الـ Taints (اللي بتطرد)، الـ Affinity بتجذب. عايز الـ Pod دي تنزل على نود قوية (Large)؟ استخدم Affinity.

أنواع الجاذبية:

  • Required: "لازم ولابد وحتماً" تنزل على النود دي. لو مفيش، الـ Pod تفضل Pending.
  • Preferred: "ياريت لو ينفع"، بس لو مفيش مكان، عادي نزلها في أي حتة.
affinity: nodeAffinity: requiredDuringSchedulingIgnoredDuringExecution: nodeSelectorTerms: - matchExpressions: - key: size operator: In values: - Large
💡 الخلاصة

Taints = "ابعد عني" (Refusal). 🚫
Affinity = "تعالى هنا" (Attraction). 🧲
عشان تخصص نود معينة لتطبيق معين ومحدش غيره يدخلها، استخدم الاثنين مع بعض.
